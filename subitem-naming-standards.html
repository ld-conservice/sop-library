Subitem Naming & Modality Standards

In one paragraph

Name every subitem [Deliverable Type]: [Descriptive Name] so anyone can tell what it is without opening it. Then set exactly one Modality per topic from the reference table below. Subitem names and file names are two different things, and the file name follows the LD Naming Convention Master.

Purpose

A subitem name is the only thing most people see. When it just says "eLearning" or "Sim," nobody can tell one deliverable from another, and the board stops being scannable. Consistent names and Modality values mean any designer, PM, or stakeholder can identify a deliverable's type and delivery format at a glance.

When to use this

  • Any time you create a subitem on a parent project item
  • Any time you rename an existing subitem
  • When you set or correct the Modality column on a topic

Before you start

  • Know the deliverable type, not just the project it belongs to
  • Confirm which Modality actually matches the deliverable rather than picking the closest guess
  • Have the LD Naming Convention Master open if you're also naming the file

Steps

  1. Name the subitem

    Use [Deliverable Type]: [Descriptive Name]. Where the deliverable lives in an authoring tool, match the descriptive name to the file name in that tool so the two stay findable together.

    Instead of thisUse this
    eLearningRise Course: Accruals Overview
    SimSimulation: Storyline [name matches Articulate file]
    Job AidJob Aid: QC Process Quick Reference
    KB ArticleKB Article: Client Exceptions Console
    VideoVideo: How to Submit an Expense Report
    MeetingsMeetings: [Project Name] (time log)
    Test / Quiz / AssessmentEvaluation: How to Request Prepayment

  2. Set the Modality

    Every topic gets exactly one Modality. Pick from this list only.

    Select thisWhen the deliverable is…
    eLearning (Rise360 / Storyline)Any self-paced digital course in Rise or Storyline, including microlearning.
    ILT / Workshop DesignAny facilitator-led session, live or virtual, that ships with a facilitator guide.
    BlendedA program that combines ILT with self-paced eLearning components.
    VideoScreen recordings, talking head, or produced training video.
    Video PostproductionCleanup work on existing footage: captions, music, name overlays.
    Voiceover VideoAdding voiceover scripting to a video or animation.
    Document / SOP / Knowledge BaseKB articles, process documentation, or reference guides.
    Job Aid / QRGQuick reference guides, checklists, process maps, or performance support tools.
    Assessment / CertificationA standalone assessment not bundled inside an eLearning course.
    TemplateReusable design templates, slide decks, or document frameworks.
    OtherOnly when nothing above fits. A note in Project Line Notes is required.
    !
    Warning

    "Other" is not a modality. It's a flag that something needs a decision. If you select it without a note, the topic can't be reported on and it won't roll up correctly in capacity planning.

  3. Name the file

    The subitem name and the file name are separate. For the file, use the LD Naming Convention Master format:

    [DocType]_[Program]_[Topic]_[Modality]_[YYYYMM]
    i
    Note

    Prefix lists, program codes, and doc type codes all live in the LD Naming Convention Master. This article covers the subitem name and the Modality field only.

Special cases

The session has both a trainer-led part and an LMS part

Don't stack two modalities on one topic. Split it: each component becomes its own topic with its own subitem, file, and Modality.

The Facilitator Guide handles sequencing between them. The file name doesn't.

Nothing in the Modality list fits

Select Other and write a note in Project Line Notes saying what the deliverable actually is and why no existing value fits.

If you hit this more than once for the same kind of deliverable, flag it to the Team Lead. That's a signal the list needs a new value, not that you should keep using Other.

You're renaming subitems on an in-flight project

Rename the subitem first, then rename the source file to match. Renaming the file first breaks the link between the board and the asset while you finish.

Note the rename on the parent item's update thread so anyone following the project can find the old name.
