## TL;DR
Name every subitem `[Deliverable Type]: [Descriptive Name]`. Pick one Modality per topic from the reference table below — never "Other" unless it genuinely doesn't fit, and if you use it, note why in Project Line Notes.

## Purpose
Standardize subitem names and Modality values so any designer can identify a deliverable's type and delivery format at a glance, without opening it.

## When to use
Every time you create a subitem or deliverable in Monday.com.

## Before you start
Know your deliverable type and confirm which Modality actually matches it — not the closest guess.

## Steps

### Step 1 – Name the subitem
Use the format below. Match the deliverable name to how it's identified in its authoring tool where applicable (e.g., a Storyline file name should match the subitem name).

| Instead of This | Use This |
| --- | --- |
| eLearning | Rise Course: Accruals Overview |
| Sim | Simulation: Storyline [Name matches Articulate file] |
| Job Aid | Job Aid: QC Process Quick Reference |
| KB Article | KB Article: Client Exceptions Console |
| Video | Video: How to Submit an Expense Report |
| Meetings | Meetings: [Project Name] (time log) |
| Test/Assessment/Quiz/Evaluation | Evaluation: How to Request Prepayment |

### Step 2 – Set the Modality
Every topic gets exactly one Modality. Select from:

| Select This | When the Deliverable Is... |
| --- | --- |
| eLearning (Rise360 / Storyline) | Any self-paced digital course in Rise or Storyline, including microlearning. |
| ILT (Instructor-Led Training) / Workshop Design | Any facilitator-led session — live, virtual, or blended — with a facilitator guide. |
| Blended | A program combining ILT with self-paced eLearning components. |
| Video | Screen recordings, talking head, or produced training videos. |
| Video Postproduction | Cleaning up a video — captions, music, name overlays, etc. |
| Voiceover Video | Adding voiceover scripting to a video or animation. |
| Document / SOP / Knowledge Base | KB articles, process documentation, or reference guides. |
| Job Aid / QRG / Reporting & Performance | Quick reference guides, checklists, process maps, or performance support tools. |
| Assessment / Certification / Knowledge Check | Standalone assessments not bundled inside an eLearning course. |
| Template | Reusable design templates, slide decks, or document frameworks. |
| Other (note required) | Only when the deliverable genuinely doesn't fit any category above. Note required in Project Line Notes. |

### Step 3 – Apply the file naming convention
Subitem names and file names are two different things. For the actual file, use the LD Naming Convention Master format:

`[DocType]_[Program]_[Topic]_[Modality]_[YYYYMM]`

Full details, prefix lists, and program codes live in the LD Naming Convention Master — this article covers the subitem/Modality field only.

## Special cases

**Blended delivery**
Every topic is assigned one Modality. When a session has both a trainer-led component and an LMS activity, treat each as a separate topic with its own subitem, file, and Modality — the Facilitator Guide handles sequencing between them, not the file name.

**"Other" Modality**
Only valid when nothing above fits. A note explaining why is required in Project Line Notes — this keeps "Other" from becoming a dumping ground.
