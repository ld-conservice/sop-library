`Intake → Project Discovery → **Learning Strategy Session** → Project Proposal → Design → Internal Review → Launch`

## TL;DR
Run the Learning Strategy Session (formerly Needs Analysis) for any project routed there by Project Discovery. Schedule it, run it, send a P.A.T.H. recap, then log your Designer Complexity Score, Est. Project Hours, Project Target Due Date, and Content Delivery Format. Your SLA clock starts the moment you log the actual meeting date.

## Purpose
Define instructional strategy for a project before design begins — objectives, delivery approach, and effort estimate — so the project enters Design with a validated scope instead of assumptions.

## When to use
Use this SOP any time a project lands in your queue in one of these two ways:
- Project Discovery sorted it into the **Learning Strategy Needed** lane (murky scope, many moving parts, high scope-creep risk).
- It started in **Proceed With Caution** and you set Designer Confirmation to **Not Straightforward – Route to Learning Strategy**.

Projects in the **Ready As Is** lane skip this SOP entirely and go straight to Project Proposal.

## Before you start
- Review the PM's Discovery Brief and intake notes on the parent item's update thread.
- Confirm the project is actually in the Needs Analysis (Learning Strategy) phase on the board.

## Steps

### Step 1 – Schedule the session
- Schedule the Learning Strategy Session with the stakeholder.
- Update **NA Meeting Scheduled Date** the moment it's booked.

### Step 2 – Conduct the session
- Record it, use the AI meeting companion, or take manual notes — your choice.
- Confirm scope, audience, objectives, and delivery approach during the meeting.

### Step 3 – Send the recap
- Send a recap to all attendees using the **P.A.T.H. method**.
- Update **NA Meeting Date (Actual)** once the meeting is complete.

> **Note:** Your Instructional Designer SLA Start Date is set automatically from **NA Meeting Date (Actual)**. If Needs Analysis isn't required on a project, the SLA clock starts from the Designer Handoff Date instead.

### Step 4 – Score complexity
- Complete your **Designer Complexity Score** using the Complexity & Readiness Scorer.

### Step 5 – Set hours and dates
- Complete **Est. Project Hours**.
- Complete **Project Target Due Date**.
- Complete **Content Delivery Format**.

## Special cases

**The stakeholder cancels last minute**
Update NA Meeting Date (Scheduled) to the new date. Do not touch NA Meeting Date (Actual) until the meeting actually happens — your SLA clock hasn't started. If they cancel twice without rescheduling, flag the PM to reassess readiness.

**A rush request is active on this project**
Check the **Project Rush Requested** column. Three rush types affect this phase differently:
- `Yes - Short notice request`: proceed as normal, compress meeting scheduling to within 2 business days.
- `Yes - Stakeholder expedited`: confirm rush budget with the Team Lead before scheduling.
- `Yes - Compressed Timeline`: run the Reverse Calendar tool with the rush budget applied before setting Project Target Due Date.

See *Handle a Rush Request* for the full workflow.
